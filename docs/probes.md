# Native probes and diagnostics (v0.1.3-preview)

The `proxy-probes-v1` worker runs separately from node discovery and heartbeats, including machines with zero logical nodes. It polls every five seconds using machine Bearer authentication, executes at most one leased task at a time and reports only bounded structured results. A recent poll advertises support. A machine with a recent heartbeat but no poll is reported as `upgrade_required`; an uncontactable machine is `machine_unavailable`. Neither is a successful test.

Exit probes instantiate an isolated embedded Xray or sing-box client, proxy a verified HTTPS request to the fixed `https://www.gstatic.com/generate_204` endpoint and require HTTP 204. User probes first project the user's actual UUID and the node's complete private/public configuration into a client outbound, connect to the node's public address and actual inbound, and traverse the configured routes/exits. They do not test only an exit or merely a TCP port. Temporary loopback SOCKS clients and all HTTP resources are closed after each attempt. The deadline is at most ten seconds; expired jobs are never executed. Target URLs, shell commands and arbitrary local configuration are not task inputs. Structured result errors never expose credentials or remote response bodies; probe creation preserves the production Xray logger and dispatcher coordination.

The source is the assigned node machine, not the user's home network. A successful request does not prove external reachability from every network. Probes use ordinary inbound authorization and may generate a small amount of actual metered traffic. MTProxy is an independent connector: its actual reported connector state is displayed separately, and generic HTTP testing returns `connector_only` rather than fabricated success.

## Administrative fault diagnosis

`POST /api/admin/nodes/:id/diagnostics {}` queues a read-only collection. Administrative `GET /api/admin/probes/:id` returns an optional `diagnostics` object after completion. This collection may run for an administrator whose proxy quota is exhausted. A completed collection is not a healthy-node assertion.

The snapshot combines the assigned node service's real kernel lifecycle flag, the panel's current eligible-user count, expected port/transport, and local `/proc/net/tcp{,6}` or `/proc/net/udp{,6}` socket bindings. UDP is never checked by TCP dial. A bound port may belong to another process; it does not verify protocol authentication or external firewall state. Unsupported operating systems return `listening:null`.

On systemd hosts the only executed command is `/usr/bin/journalctl` or `/bin/journalctl` with fixed arguments `--unit=caddy.service --since=-10min --lines=120 --no-pager --output=cat`, a three-second deadline, a minimal environment, and at most 64 KiB captured output. OpenRC fallback reads only fixed regular `/var/log/caddy.err` and `/var/log/caddy.log` files, at most 64 KiB each; only ISO-timestamped lines within ten minutes count. If recent logs cannot be established, the result states that logs are unavailable.

Raw lines never leave the process. Known address-in-use, authentication, configuration-start and certificate/TLS patterns become fixed codes/messages and counts. These are explicitly machine-level evidence and may concern another logical node. The panel validates the structured schema, maps every message to its own fixed allowlist, and exposes diagnostic evidence only through administrator result endpoints.

## Public addresses without WARP contamination

`status.public_addresses` contains IPv4/IPv6 arrays, `source:physical_interface`, and `detected_at`. Only UP, non-loopback, non-point-to-point interfaces with a confirmed Linux `/sys/class/net/<name>/device` are considered. WARP/TUN/TAP/WireGuard and other virtual names, private/CGNAT/link-local/documentation/reserved addresses are excluded. No external IP-echo service is contacted and no route/WARP configuration is modified. IPv4 is preferred by the panel, then IPv6. NAT-only hosts, containers without physical interface proof, and unsupported operating systems can legitimately return empty arrays; enter a verified public address manually in that case.

## Existing-machine update

This release's binary version contains `-luma-v2`; previous immutable preview releases remain unchanged. Generate a fresh automatic connection command for the **same saved machine**, then run that command on its already installed host. The existing enrollment path validates panel/machine/config/credential references and known service environment before staging/replacing the verified binary pair. It preserves node/kernel/IP-family configuration and credential-file binding, and rotates machine authentication through the existing enrollment claim. Conflicting bindings, inline/custom identity overrides and matching independent connectors retain their refusal safeguards. Do not remove the install directory or rerun an unrelated fresh-install command. Generic unverified automatic upgrades remain disabled.

## Landing Ping latency

Following a successful authenticated exit proxy roundtrip, the node sends up to three ICMP echo requests to that saved landing address and reports the average matching-reply RTT as `ping_ms`. The target address is generated by the panel from the saved exit, not supplied by a browser or arbitrary command. Echo destination, identifier, sequence and random payload must all match. Resolution and ICMP are bounded by the remaining job deadline and a maximum three-second ICMP budget; raw sockets close after use. No ping subprocess or shell is executed. Proxy HTTP elapsed time is not displayed. Direct and user-inbound checks without a selected landing do not invent Ping latency. ICMP blocked/timeouts, name-resolution failure, or unavailable raw-socket capability are separate `ping_error_code` results and never turn a successful proxy request into a false proxy failure. Native services normally run as root; limited-capability hosts must grant ICMP permission to measure RTT.
